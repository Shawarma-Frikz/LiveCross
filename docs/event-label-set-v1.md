This is the first versioned project event-label table. It demonstrates the schema and records a limited visual-review pilot without treating DOT's run-level source labels as event labels. ## Label guide and frozen v1 rule

The v1 manual profile is **visual-categorical-v1.0.0**, frozen 15 November 2026 before any test prediction or test annotation was viewed. Apply the three statuses in [manual-annotation-protocol.md](manual-annotation-protocol.md):

- **potential_conflict:** visible evidence supports contemporaneous occupation of the same crossing/conflict area or a clearly evasive/impact-like interaction. This is a review label, not a crash determination.
- **non_conflict_interaction:** the same identifiable pair is observable through the complete review window and its paths remain visibly separated without a conflict cue.
- **uncertain:** identity, visibility, timing, or motion evidence is insufficient. Keep it out of binary training and primary metrics.

Use exact CSV frame timestamps; never derive event time from nominal FPS. Record the smallest interval supported by reviewed evidence, and mark approximate boundaries in the uncertainty field. Do not assign a pair label from a DOT run label, from a model alert, or from a route intersection alone. Fixed-object categories require a stable scene hazard ID and a documented image-plane footprint/buffer before annotation; no such hazard map is frozen for this pilot, so those categories remain unannotated.

The category rules are qualitative at this pilot stage. No numeric time-to-collision or pixel-distance threshold is claimed as frozen. The later scoring phase must define and freeze model scoring thresholds on training/development data before any held-out test predictions are opened. Any change to this manual profile requires a new version and a dated reason; never overwrite v1 rows silently.

## Review provenance and limits

The default review pack covers development runs. To build the broader, test-excluded train/development survey pack:

~~~powershell
python scripts/build_annotation_review_pack.py --splits train validation
~~~

It writes timestamped one-second contact sheets and a frame manifest under Git-ignored data/processed/annotation-review-1s/. These downsampled sheets help locate candidate windows, but labels must be checked against continuous source video before being accepted. Focused review can use a smaller interval, for example:

~~~powershell
python scripts/build_annotation_review_pack.py --runs Run_1165 --interval 0.25
~~~

Test run IDs are rejected by the pack builder. The v1 CSV records a first-pass visual review by codex_visual_first_pass; this is **not an independent human annotation**. The Run_1165 and Run_294 candidates show a pedestrian down as a vehicle reaches or crosses the marked crossing. Both are labeled potential conflict without asserting that a collision occurred; their boundaries and temporary IDs need student frame-level confirmation. Run_294's focused preview can be regenerated with `python scripts/build_annotation_review_pack.py --splits train validation --runs Run_294 --interval 0.25 --start-frame 340 --end-frame 800`. The Run_841 pedestrian-pair window is uncertain; Run_632 and Run_1194 are excluded for inadequate visibility. No pair label is inferred solely from co-presence in contact sheets.

## Ground-truth release checklist

Do not use this draft CSV as the project ground-truth target yet. For each candidate, review the original continuous video around the proposed interval, record exact timestamp/frame boundaries, confirm both actor identities and pair type, and either accept or correct the label. Replace the draft annotator/review stage with the student's identifier and `student_adjudicated` only after that review. Keep unresolved cases `uncertain` with a reason; do not convert them to negatives. The solo-project limitation must remain disclosed. Generate the summary again after every table change and verify the table hash and counts in the JSON. The v1 set currently has **zero adjudicated labels** and does not meet any category's acceptance target. The five-category set also cannot be fully populated from the inspected DOT sample alone; additional permission-cleared footage and a frozen fixed-hazard map are needed for broader pair types.

Run the summary generator after editing the annotation CSV:

~~~powershell
python scripts/summarize_event_annotations.py
~~~

The generator validates rows, verifies each labeled run against data/manifests/splits.csv, checks each frame index against the exact timestamp in the source archive's camera timing CSV, summarizes counts and annotated-window duration by split and pair type, lists uncertain/excluded examples, records actual annotation provenance separately from generated-pack inventory, and marks each category exploratory until it has at least 20 adjudicated potential-conflict and 20 adjudicated non-conflict windows across at least five distinct source runs. Current labels do **not** meet that target in any category. All five categories remain exploratory; no event-level performance claim is supported.
