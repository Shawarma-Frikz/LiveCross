## Label guide and frozen v1 rule

The v1 manual profile is **visual-categorical-v1.0.0**, frozen 15 November 2026 before any test prediction or test annotation was viewed. Apply the three statuses in [manual-annotation-protocol.md](manual-annotation-protocol.md):

- **potential_conflict:** visible evidence supports contemporaneous occupation of the same crossing/conflict area or a clearly evasive/impact-like interaction. This is a review label, not a crash determination.
- **non_conflict_interaction:** the same identifiable pair is observable through the complete review window and its paths remain visibly separated without a conflict cue.
- **uncertain:** identity, visibility, timing, or motion evidence is insufficient. Keep it out of binary training and primary metrics.

Use exact CSV frame timestamps; never derive event time from nominal FPS. Record the smallest interval supported by reviewed evidence, and mark approximate boundaries in the uncertainty field. Do not assign a pair label from a DOT run label, from a model alert, or from a route intersection alone.

The category rules are qualitative at this pilot stage. No numeric time-to-collision or pixel-distance threshold is claimed as frozen. The later scoring phase must define and freeze model scoring thresholds on training/development data before any held-out test predictions are opened. Any change to this manual profile requires a new version and a dated reason; never overwrite v1 rows silently.

## Review provenance and limits

The default review pack covers development runs. To build the broader, test-excluded train/development survey pack:

```powershell
python scripts/build_annotation_review_pack.py --splits train validation
```

It writes timestamped one-second contact sheets and a frame manifest under Git-ignored `data/processed/annotation-review-1s/`. These downsampled sheets help locate candidate windows, but labels must be checked against continuous source video before being accepted. Focused review can use a smaller interval, for example:

```powershell
python scripts/build_annotation_review_pack.py --runs Run_1165 --interval 0.25
```

Test run IDs are rejected by the pack builder. The `Run_1165` and `Run_294` rows are based on the student's continuous-video review. The `Run_889`, `Run_942`, and `Run_87` rows were explicitly adopted by the student from assistant first-pass proposals; no separate student playback is recorded for those intervals. Actor IDs are reviewer-assigned placeholders. The `Run_87` label remains `uncertain`, not binary. Potential-conflict labels do not assert collision or fault. `Run_632` and `Run_1194` remain excluded for inadequate visibility. This is solo review; no independent second annotator is claimed.

## Ground-truth release checklist

Use this small CSV only as an exploratory pilot, not as sufficient ground truth for primary metrics. For each candidate:
1. Review the original continuous video around the proposed interval.
2. Record exact timestamp/frame boundaries from source timing CSV.
3. Confirm both actor identities and pair type.
4. Accept, correct, or mark uncertain.
5. Record whether the student reviewed the clip or explicitly adopted an assistant proposal. Keep unresolved cases `uncertain` with a reason; do not convert them to negatives.
6. The solo-project limitation must remain disclosed. Generate the summary again after every table change and verify the table hash and counts in the JSON.

The v1 set currently has **three student-adjudicated pedestrian–vehicle potential-conflict windows (one assistant-assisted), one assistant-assisted student-adjudicated pedestrian–vehicle non-conflict window, and one assistant-assisted student-adjudicated but uncertain vehicle–vehicle window**. Neither category meets its sample gate.

Run the summary generator after editing the annotation CSV:

```powershell
python scripts/summarize_event_annotations.py
```

The generator validates rows, verifies each labeled run against `data/manifests/splits.csv`, checks each frame index against the exact timestamp in the source archive's camera timing CSV, summarizes counts and annotated-window duration by split and pair type, lists uncertain/excluded examples, records actual annotation provenance separately from generated-pack inventory, and marks each category exploratory until it has at least 20 adjudicated potential-conflict and 20 adjudicated non-conflict windows across at least five distinct source runs. Current labels do **not** meet that target in either category. Both categories remain exploratory; no event-level performance claim is supported.
